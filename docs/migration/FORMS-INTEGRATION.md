# Forms integration

`POST /api/forms` accepts JSON `{ formType, route, fields }` and a client-supplied `Idempotency-Key` header (8–200 ASCII characters). The same key must be reused for a retry. A successful hand-off returns `202`; invalid requests return `400`, `403`, `404`, or `422`; unavailable/retryable delivery returns `503` with the provider's valid `Retry-After` value or 30 seconds. The endpoint never reports success when the adapter fails.

Requests must declare the current production origin (`https://joaquimmota.pt` or `https://www.joaquimmota.pt`). Local development permits Astro (`http://localhost:4321`, `http://127.0.0.1:4327`) and the Cloudflare Pages preview listener (`http://localhost:8789`, `http://127.0.0.1:8789`) only. The endpoint measures the received body and rejects bodies over 16 KiB even when `Content-Length` is absent or inaccurate.

The Astro client must submit only these fields. `email` is required for every form and `name` is required for `contact`; all other listed fields are optional strings: `newsletter` — `email`, `firstName`, `lastName`; `contact` — `name`, `email`, `phone`, `message`; `valuation` — `name`, `email`, `phone`, `propertyType`, `bedrooms`, `location`, `message`; `mortgage` — `name`, `email`, `phone`, `message`; `partnership` — `name`, `email`, `phone`, `clientType`, `message`; `leadMagnet` — `name`, `email`, `phone`, `message`. The server rejects unknown fields, unknown form types, and any route outside its type-specific allowlist.

The request type and route must be one of the server allowlist. `newsletter` accepts its documented fields on its static routes and eligible `/imoveis/{sourceSlug}` or `/post/{sourceSlug}` routes. `contact` additionally accepts eligible property routes. These CMS slugs are generated from the gated eligibility report in [allowed-source-routes.json](../../functions/api/allowed-source-routes.json); eligibility itself determines inclusion. Newsletter capture uses the current global Resend Contacts endpoint and does not send a marketing message. Lead notification uses a separate sending key.

The current inventory records public forms on contact, newsletter, valuation, mortgage, partnership, and lead-magnet routes. The `/doop/relatorios-*` tracking/report routes are excluded from this public lead endpoint pending a separate destination and access review; public availability alone does not establish authentication. Their preview controls do not send records. Existing public form copy and consent behavior stay in Astro; this endpoint does not add double opt-in or change copy.

Required server-only variables are in `.env.example`. Configure the recipient through `FORMS_RECIPIENT`; the source public contact address is evidence, not a hard-coded delivery decision. Do not expose these values to client code. The Resend adapter is tested with mocks; no provider call, email, contact creation, or webhook is performed by this migration task.
